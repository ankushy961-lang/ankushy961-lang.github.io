Mikazuki · voice OS

A voice OS for one person, running on the phone itself

6 November 2026 · 4 min read

Mikazuki is an Android voice operating system built for one user, not a crowd. It hears a wake word on the device, plans with one of three brains, recalls from a vector memory, and carries out the action on the phone itself through the accessibility service.

Why build a voice OS for one person?

Most assistants are built for millions of accounts at once. They answer the average question well and your particular question poorly. They cannot know your habits, because knowing them at that scale is a privacy problem and a storage problem.

Mikazuki turns that around. There is one user, one phone and one memory. Every design choice follows from that: the memory can be personal, the brain can be local, and the assistant can be trusted to touch the phone's own settings.

The name is the kanji for the three-day moon, a thin crescent. The crescent is also the button you tap to talk. Version 1.0.0 has shipped.

What changes when an assistant remembers?

A stateless assistant starts every conversation from zero. You repeat your context each time, and it repeats its questions. The work of remembering stays with you.

Mikazuki keeps long-term memory in a SQLite database on the phone, with the sqlite-vec extension for vector search. When you say something worth keeping, it is stored as text plus a numeric fingerprint of its meaning. The memory file lives on the device, not on a server.

The effect is small on the first day and large after a month. You stop explaining who people are, which alarm you mean, or what you decided last week. The assistant holds the thread.

How does memory recall work in plain terms?

Each memory is turned into a list of numbers that describes its meaning. Two memories about the same subject end up with similar lists, even when they use different words. That is what a vector is here: a position, not a keyword.

When you speak, your request gets the same treatment. Mikazuki asks sqlite-vec for the stored memories whose positions sit closest to the request. The nearest few are handed to the planner as context before it decides what to do.

  • Say "set the usual alarm" and recall finds the memory where you said which time is usual.
  • Ask "what did I say about the trip" and recall finds that note, even if you never used the word trip when you saved it.
  • Nothing is matched by exact text, so a different phrasing still works.

The planner never sees the whole memory. It sees the few entries that matter for this request, which keeps the prompt short and the answer on topic.

Why does on-device execution matter?

Many assistants can talk about an action but cannot perform it. They open a web page, or they hand you a button to press. The last step still belongs to you.

Mikazuki runs an Android accessibility service. That service can read the screen and perform the taps and inputs a person would, inside the apps already on the phone. When the planner decides to set an alarm, the service sets it, on the device you are holding.

This has three consequences. The action can complete without a network when the on-device brain is used, and it needs no separate integration with each app. The result is visible on screen, so you can check what was done.

What are the three brains, and what are the crew worlds?

The planner can use a cloud brain or an on-device brain, three brains in total. A cloud brain needs a connection; the on-device brain does not. The planner picks, so a simple request does not have to leave the phone.

Speech output runs at 24 kHz. The server side is a Bun + Hono service, kept small because most of the work happens on the device.

The look is set by ten themed crew worlds, inspired by a manga crew. Each world changes the colours and the motion around the crescent; the effects are AGSL shaders. It is a small thing that makes a tool for one person feel like it belongs to that person.

Stack and numbers. Kotlin, Jetpack Compose and AGSL shaders on Android; a Bun + Hono server; SQLite with sqlite-vec for memory. Version 1.0.0 shipped, 3 brains, 10 crew worlds, 24 kHz speech output.
